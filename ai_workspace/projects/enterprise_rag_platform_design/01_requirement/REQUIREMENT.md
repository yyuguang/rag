# 项目名称

企业级 RAG 知识库问答平台

# 项目背景

企业内部文档通常分散在制度、产品、研发、售前、售后、运维、接口文档、手册和知识库系统中。传统关键词搜索只能返回文档列表，用户仍需自行阅读、筛选和理解。RAG 系统通过“检索企业可信资料 + 大模型生成答案 + 引用来源”的方式，把静态知识转化为可问答、可追溯、可权限控制的企业 AI 能力。

# 项目目标

构建一个接近真实企业可落地的 RAG 知识库问答平台，支持文档上传、解析、清洗、切片、向量化、索引、混合检索、Rerank、Prompt 组装、大模型流式回答、引用来源、多轮会话、权限隔离、用户反馈、调用日志、Token 统计、成本控制和可观测性。

# 用户角色

- 平台管理员：管理租户、用户、角色、模型配置、系统配置和审计日志。
- 租户管理员：管理本租户用户、部门、角色、知识库和用量。
- 知识库管理员：创建知识库、维护文档、配置可见范围和重建索引。
- 普通用户：在授权范围内提问、查看会话、提交反馈。
- 运营 / 质检人员：维护问答评测集、分析反馈、优化知识库与 Prompt。

# 用户场景

## 场景 1：企业内部知识库问答

员工在问答界面输入制度、流程或产品问题，系统检索其有权限访问的知识库，生成带引用的回答。

## 场景 2：客服 / 售后支持

客服根据客户问题快速查询产品手册、售后 FAQ、故障处理文档，减少转人工和重复查询。

## 场景 3：研发文档助手

研发人员查询接口文档、部署说明、故障复盘和架构规范，系统给出答案并引用原文片段。

## 场景 4：运维知识库助手

运维人员查询告警处理流程、SOP、巡检手册和故障案例，系统优先返回可执行步骤和注意事项。

# 功能需求

## FR-1 用户登录与权限

- 描述：支持用户、角色、部门、租户、多级权限和会话访问控制。
- 输入：账号凭证、Token、租户 ID、角色授权、部门关系。
- 输出：登录态、用户权限、知识库可见范围、操作授权结论。
- 约束：所有业务接口必须鉴权；禁止越权访问文档、会话、知识库和引用来源。

## FR-2 知识库管理

- 描述：支持创建、修改、分类、启停、可见范围配置和统计。
- 输入：知识库名称、描述、分类、租户、可见范围、Embedding 配置、检索配置。
- 输出：知识库详情、统计信息、权限配置。
- 约束：知识库归属租户；知识库管理员只能管理授权知识库。

## FR-3 文档管理

- 描述：支持 PDF、Word、Markdown、TXT、Excel、网页内容、接口文档、产品手册、制度和售后文档上传与处理。
- 输入：文件、URL、文档元数据、所属知识库、权限范围。
- 输出：文档状态、解析结果、Chunk、索引状态、失败原因。
- 约束：文档处理异步执行；支持版本、删除、重建索引和失败重试。

## FR-4 RAG 问答

- 描述：支持自然语言提问、查询改写、意图识别、向量检索、关键词检索、混合检索、Rerank、Prompt 组装、大模型生成、流式输出、引用来源和多轮会话。
- 输入：问题、会话 ID、知识库范围、检索参数、模型参数。
- 输出：流式答案、引用片段、追踪 ID、Token 用量、成本。
- 约束：模型只能基于授权检索上下文回答；无答案时拒答；引用必须可追溯。

## FR-5 反馈与评估

- 描述：支持点赞、点踩、文本反馈、答案评分、检索命中率统计、人工标注和评测集。
- 输入：消息 ID、反馈类型、评分、标签、问题修正建议。
- 输出：反馈记录、质量报表、评测结果。
- 约束：反馈不得泄露其他租户或无权限文档内容。

## FR-6 系统管理

- 描述：支持模型配置、Prompt 模板管理、Token 用量统计、成本统计、调用日志、异常日志、限流和敏感词配置。
- 输入：模型供应商配置、Prompt 版本、限流策略、敏感词规则。
- 输出：配置生效状态、统计报表、审计记录。
- 约束：API Key 必须加密存储；敏感字段日志脱敏。

# 非功能需求

## 性能要求

- 文档上传后异步处理，大文件不阻塞用户请求。
- 单次检索目标延迟：MVP P95 小于 1.5 秒，生产 P95 小于 800 毫秒。
- 首 Token 响应时间：MVP 小于 5 秒，生产小于 3 秒。
- 支持并发问答、文档处理任务队列和模型调用限流。

## 可扩展性要求

- 支持多个模型供应商、多个向量库、多种文档解析器和水平扩展。
- RAG 策略、Prompt 模板、Embedding 模型和 Rerank 模型应配置化。

## 高可用要求

- 模型调用支持超时、重试、熔断和降级。
- 文档处理任务支持 MQ 削峰、失败重试和死信队列。
- 后端服务尽量无状态，依赖 Redis / DB / MQ 管理状态。

## 安全要求

- 多租户隔离、文档权限过滤、API 鉴权、敏感信息脱敏、Prompt Injection 防护、日志脱敏、恶意文件检测和 API Key 保护。

## 可观测性要求

- 记录 traceId、模型调用耗时、Token 消耗、成本、检索命中率、向量库耗时、Rerank 耗时、异常告警和用户满意度。

# 事实 / 假设 / 待确认问题

## 事实

- 用户技术背景是 5 年 Java 后端工程师。
- 用户要求输出企业级 RAG 平台完整设计方案。
- 当前仓库有 `.ai_rules`、core skill 和 AGENTS 流程约束。

## 假设

- MVP 面向个人开发者 8 周完成，优先采用模块化单体。
- 企业内部部署允许使用 Docker Compose 起步，生产可迁移 Kubernetes。
- 企业文档默认需要权限隔离，且问答答案必须可追溯引用来源。

## 待确认问题

- 目标企业规模、文档量、并发 QPS 和预算上限。
- 优先使用公有云模型还是本地私有化模型。
- 是否已有 SSO / LDAP / OAuth2 / 企业微信 / 钉钉等统一身份源。
- 是否要求国产化数据库、中间件或离线部署。
